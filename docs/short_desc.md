# какую задачу решаем

Данные — взаимодействия пользователей с видео, упорядоченные во времени и разбитые на файлы по неделям. Работаем в постановке next-item prediction (NIP): по истории пользователя предсказать следующий позитивный айтем.

Пусть U — пользователи, I — каталог сабсета. История пользователя u — хронологически упорядоченная последовательность позитивных взаимодействий $S_u = (i_1, …, i_m)$.

Модель $f_θ(S_u^{<k}) → R^{|I|}$ выдаёт скор по всему каталогу; рекомендация — top-K после фильтрации уже показанного. Оптимизируем ранг истинного $i_k$. Все сравниваемые модели непоследовательные: историю они получают как множество, порядок внутри неё не используют.

Сплит — глобальный по времени, чтобы не было утечки из будущего: последняя неделя — test, предпоследняя — val, всё, что раньше, — train. Для пользователя таргет — его первый позитив в тестовой неделе, история — всё, что было до начала этой недели.

filter seen включаем: в VK-LSVD нет повторных показов пары пользователь–видео, значит уже показанное видео не может быть правильным ответом, и оставлять его в выдаче — искусственно занижать метрику. Фильтруем все показанные пользователю видео, а не только позитивные.

Основное определение (base positive):

$positive(u, i) = like ∨ share ∨ bookmark ∨ click\_on\_author ∨ open\_comments
                 ∨ (timespent / duration ≥ 0.5)$

# какие данные используем

VK-LSVD. Подробное описание датасета и сабсеты для экспериментов — в VK-LSVD_subset_plan.md.

# какие подходы можно сравнить

Два уровня: тривиальные бейзлайны (проверка, что модели выучили что-то сверх популярности) и классическая CF (её просили в кейсе).

Каждая CF-модель запускается в двух вариантах: без контента и с контентными эмбеддингами. Основной результат работы — разница метрик между этими вариантами для одной и той же модели, а не сравнение моделей между собой.

| Группа | Модель | Роль | 
| --- | --- | --- |
| Bare | `MostPopular` (по последней неделе train) | Нижняя граница, детектор popularity bias |
| Bare | `Random` | Санити-чек метрик |
| CF | `iALS` (implicit) | Классическая матричная факторизация | 
| CF | `EASE^R` | Сильный непараметрический item-item бейзлайн, часто бьёт нейросети | 
| CF | `LightFM (WARP)` | Гибрид «из коробки» | 

# как будем оценивать результат

По оффлайн-метрикам на полном каталоге сабсета, K ∈ {10, 15, 20}:

- NDCG@K — качество ранжирования: насколько высоко в выдаче стоит правильный айтем.
- Recall@K — качество ретривала: попал ли правильный айтем в top-K.
- Coverage@K — доля каталога, попавшая хотя бы в одну выдачу: |∪_u topK(u)| / |I|.
- Diversity@K — разнообразие внутри выдачи одного пользователя: доля уникальных авторов (категорий) в top-K, усреднённая по пользователям.
